# 重构审阅问题与修复建议

Status: proposed

## Problem

审阅基准为重构前的 `ae461aa9ddd5a8f5e445459e14f5d611921f9938`，审阅对象为 `a52a4c66a9e75d86c130be2e029345a761829c24`。本提案覆盖代码审阅发现，以及测试反馈中的 fallback 报错、取消等待和离线运行库打包失败。安装身份与注册表写入见[根据安装记录决定注册行为](./2026-09-20-install-identity-registry.md)。下面区分重构引入的问题、未说明的行为变化、旧问题与应保留的设计；修复建议尚未实施。

### 应保留的设计

更新时保留已有 `userDataPath` 文件、补齐缺失的默认文件；非空 `ignoreFolderPath` 跳过更新；运行库安装失败提示用户后允许应用文件安装结束。这些行为有明确用途，不因代码审阅而统一改成失败或覆盖。[计划生成](../../../native/session/plan.rs)与[运行库安装](../../../native/session/run.rs)是对应实现。绿色版不创建注册记录见[安装身份提案](./2026-09-20-install-identity-registry.md)。

[文件提交协议](../implemented/2026-09-02-atomic-file-commit.md)规定提交阶段不可取消、暂存写入停止后才能清理，以及中断恢复和自更新处理。本提案保留这些规则，修复进入提交前的取消判定和等待反馈，不增加提交中取消。

## Proposal

### 保留真实失败，区分用户取消与连带中止

下载任务首次发生实际失败时保存该错误；其他任务因这次失败停止时只返回中止结果，不构造新的用户可见错误。可复用现有跳过任务的表示，避免为此建立通用任务调度框架。错误选择不依赖任务在列表中的位置。用户取消仍由取消 token 表示，不能把所有含 `cancelled` 文本的错误当作用户取消。

fallback 收到非空失败列表却没有有效文件可处理时，属于调用数据不符合预期，应单独保留诊断，不能与用户取消或其他任务失败混为一谈。实际下载错误继续按现有错误码展示和上报，遵守 [UI 契约](../implemented/2026-09-02-ui-contract.md)。目前没有与反馈截图对应的完整日志，不能认定截图背后的首次失败是超时、网络中断或具体服务端错误。

### 取消立即反馈，提交前由会话统一决定

接受取消后立即显示“正在取消，等待当前任务结束并清理临时文件”，停止启动新任务，并让 WebView 与 native 界面都显示取消中的状态。已经完成的下载进度不能把取消文案覆盖回去。只有写入操作停止、必要清理完成后才返回首页。

把“接受取消”与“进入不可取消的提交阶段”放在同一处会话状态转换中决定。取消先被接受就不得调用提交；提交状态先建立则拒绝新的取消，并让界面展示不可取消状态。该决定必须在准备自身映像等最后一个可等待步骤之后执行，覆盖 DFS、Mirror酱 和已最新但需要刷新自身映像的路径，不能只在下载结束时补一次 token 检查。

保留 `wait_idle` 所保护的清理顺序，不能超时后直接删除仍有任务写入的暂存目录。先修复状态反馈和提交窗口，不承诺点击后瞬时结束。若需要缩短等待，复用会话取消信号，使提权侧的下载、扫描和解压在适当的 I/O 或循环边界停止；只传递本次会话所需的取消，不扩展成通用逐请求取消系统。远端会话结束请求不得无限阻塞本地收尾，应复用已有请求超时并检查是否覆盖整个等待过程。等待原因和取消被接受的时点保留简短日志，便于区分远端收尾与本地在途操作。

### 按 Windows 普通文件名校验，保留生产打包格式

普通嵌入名称采用兼容普通 Win32 文件 API 和资源管理器的单个文件名规则，允许中文、内部空格、`+`、括号等合法字符；拒绝空名称、路径分隔符、`< > : " | ? *`、NUL、U+0001 至 U+001F、`.`、`..`、尾随空格和句点，以及 Windows 设备保留名及其带扩展名形式。设备名判断忽略大小写并覆盖 Windows 识别的 COM/LPT 数字形式。路径清单仍走相对路径校验，不能把整个 `Assets/a.bin` 当单个嵌入名称处理。命令执行处负责正确传参，不以禁用 `&` 等合法文件名字符代替 shell 安全。

包内的 `\0CONFIG`、`\0META`、`\0INDEX`、`\0IMAGE`、`\0THEME` 保留精确的内部名称例外，普通条目不得借此接受任意 NUL。将共用名称规则放在 builder 和 installer 都能使用的位置，写入、扫描和提取复用它，避免维护三份相同白名单。

[打包编码](../../../native/builder/pack.rs)与[读取解码](../../../native/local.rs)表明，生产格式存在两种名称长度字段：

| 使用位置 | 现有编码与限制 | 预期处理 |
|---|---|---|
| 普通 TLV 条目头 | 大端 `u16`，名称为 UTF-8 字节，字段最多表示 65,535 字节 | 保留字段宽度、字节序、魔数和排列。移除读取器任意的 512 字节上限，以字段长度、剩余文件长度及名称合法性检查读取；写入使用检查转换，超出字段范围明确报错。 |
| `\0INDEX` 内每个名称 | `u8`，最多 255 个 UTF-8 字节 | 保留 255 字节上限；写索引前检查并报错，禁止 `as u8` 截断。普通条目未写入索引时，不额外施加这个上限。 |

512 字节检查不存在于基准版本，且不是上述字段能表达的上限。移除它不需要改变生产格式。Windows 文件名长度与包内 UTF-8 字节数是不同约束，不能把字节数称为字符数；本提案不通过改成宽字符编码来解决长度问题。

`append` 不重建索引，名称规则应允许原样保存运行库 tag，不能用删除 `+`、改名或 Unicode 规范化绕过限制。所有可预先判断的名称和长度错误应在创建、截断或追加输出前完成校验，并报告条目名、实际字节数及违反的限制。读取端保留截断数据、偏移越界和 UTF-8 合法性检查；这些直接保护包解析，不扩展为新的包格式或扫描框架。

### 修正 Mirror酱 元数据定位

归档内控制文件的位置决定目录解释：根目录存在 `.metadata.json` 时，保留根目录下真实文件路径；只在归档结构明确表示一个外层包装目录时剥除该目录。`changes.json` 的现有支持保留。不能仅凭所有变更文件恰好位于一个子目录推断包装目录。已注册版本的登记修复见[安装身份提案](./2026-09-20-install-identity-registry.md)。

### 处理其余审阅问题

| 问题 | 预期修复方式 |
|---|---|
| 暂存 ACL 随 rename 进入目标 | 提交前按最终安装位置处理新文件和新目录的权限，保留已有目标明确设置的权限；同时保证提权写入期间暂存内容不受无权限主体替换。沿用同卷暂存与原子提交，先在受保护目标和普通用户目录验证实际 ACL，再确定最小的权限处理位置，不递归重置整个既有安装目录。 |
| 退出清理 shell 解析 | 使用不经 shell 解释路径的清理进程，通过结构化参数传递唯一暂存根、等待父进程退出后调用文件系统 API 删除。复用现有进程启动设施；清理进程的运行镜像必须在待删目录之外，并解决自身临时副本的清理，避免删除被自身占用的目录。删除范围限定为本次记录的暂存根，不增加扫描历史目录的常驻清理程序。 |
| CDK 取消未恢复 | 输入值在验证成功前保持为候选值；成功后提交 CDK、验证状态和凭据存储，取消或失败保留已确认值。来源切换后迟到的验证结果不得覆盖新来源，不新增全局状态框架。 |
| 隐藏来源入口消失 | 建议恢复临时显示隐藏来源的入口，沿用 `hidden` 配置和原有可发现方式。若决定移除该能力，应作为明确的产品变更记录，不能仅因渲染器重写而消失。 |
| 空安装列表跳过删除与运行库 | “已最新”按整个待执行计划判断；无文件写入时仍执行删除与需要的收尾，不引入另一套更新流程。已注册版本在无文件写入时的登记修复见[安装身份提案](./2026-09-20-install-identity-registry.md)。 |
| 卸载保留用户数据失效 | 未选择删除用户数据时，从普通文件删除清单中排除 `userDataPath` 覆盖的路径；勾选后按现有配置删除。路径比较使用现有规范化与目录包含判断，保留包内默认数据和运行期数据的相同语义。 |
| 卸载忽略删除失败 | 正确收集实际文件操作错误，缺失文件仍视为已删除；部分失败时显示未完全卸载，并保留重试所需的安装信息，不直接宣告完成。无需为每个文件增加重试状态机。 |

## Alternatives considered

- 仅把 `+` 加入字符白名单：能修复当前运行库名称，仍会拒绝中文、空格等合法名称，也无法解决 512 字节限制及读写规则分散。
- 将全部名称长度统一为 255 字节：实现简单，但把索引的格式限制施加给未索引条目；将索引长度字段扩为 `u16` 则破坏生产格式。保留现有两种编码，只统一各自的校验来源。
- 把 `merged fallback cancelled` 统一映射成用户取消：会隐藏其他任务的真实失败；只隐藏弹窗同样无法恢复错误原因。
- 取消时立即返回首页或直接结束提权进程：在途任务可能继续写入，或破坏同时承担收尾工作的执行进程。保留停止写入后清理的顺序，先反馈取消状态。
- 为缺少 metadata 的 Mirror酱 归档强制报错，或把增量归档内容当完整文件清单：前者取消现有支持，后者丢失未变更文件的卸载信息。路径解释按上文修正；登记兼容策略见[安装身份提案](./2026-09-20-install-identity-registry.md)。
- 为所有来源、提权方式、取消时点和文件名增加 e2e 组合：维护成本高，且实际网络、调度和 UAC 易导致偶发失败。匹配规则和时序分支使用确定性单测，操作系统权限另用少量隔离 Windows 场景验证。注册表链路验收见[安装身份提案](./2026-09-20-install-identity-registry.md)。

## Acceptance criteria

### 必须满足的行为

1. `Microsoft.VCRedist.2015+.x64`、`Microsoft.VCRedist.2015+.x86` 可按原 tag 追加并由安装器找到；合法中文和空格名称可读写。512 不再成为独立限制，TLV 与索引的既有字段宽度、编码和排列不变。格式超限错误发生在修改输出之前，并说明具体条目和字节限制。
2. 并发任务失败后，连带中止不替代真实错误；实际用户取消不作为内部错误上报。取消立即产生可见状态，取消先被接受时不得开始提交，进入提交后不能接受取消。暂存目录删除发生在写入任务结束之后。
3. Mirror酱 根目录控制文件与实际子目录路径正确识别。
4. 安装到受保护目录后，新文件权限符合目标位置要求；清理路径中的 shell 特殊字符不会改变删除范围。取消 CDK 编辑保留原有效配置；隐藏来源的行为有明确结论；纯删除更新不被当作无事可做；卸载保留用户数据并报告实际删除失败。

### 测试场景与预期结果

下表列出需要验证的行为，优先向现有用例补充输入或断言。单测中的执行顺序用通知信号或可控 future 安排，不依赖固定 sleep 或真实网络。各行可以共用测试文件和夹具。

| 验证对象 | 要测试的场景 | 预期结果与验证方式 |
|---|---|---|
| 名称校验 | 两个含 `+` 的 VC 运行库 tag、中文、内部空格；路径分隔符、设备名、尾随点或空格、普通名称中的 NUL；精确的内部保留名 | 共用表驱动单测验证允许与拒绝范围；运行库 tag 原样往返，内部名称例外不放宽普通名称 |
| 打包格式与长度 | UTF-8 多字节名称；超过 512 字节的可接受普通 TLV 名称；索引 255/256 字节边界、TLV 长度字段边界；截断、非法 UTF-8 和偏移越界 | 固定字节样例验证原有编码及新读取器读取既有格式；超限在修改输出前失败，已有输出字节保持不变，错误包含条目和限制；两类读取器复用样例 |
| 真实错误与连带中止 | 一个任务真实失败，另一个 fallback 连带中止，调整两者完成次序和任务排列；用户主动取消；非空失败列表没有有效索引 | 原始失败不被连带中止替代，用户取消不弹内部错误，无有效索引保留独立诊断；使用会话单测验证错误类型和最终选择 |
| 取消与提交顺序 | 在最后一次提交前准备等待中接受取消；先进入提交再收到取消；取消时提权写入尚未结束 | 前者不提交，后者拒绝取消；接受取消时立即发布状态并停止启动新任务，在写入和清理结束后才返回首页；复用会话与 `wait_idle` 测试，覆盖 DFS、Mirror酱 及需要刷新自身映像的已最新路径 |
| 取消等待反馈 | 操作已接受取消但暂未结束，期间继续收到普通进度 | WebView 和 native 持续显示取消收尾状态；确认等待发生在何处，不能以按钮禁用代替受理反馈；组件测试配合一次可控慢操作的人工检查 |
| Mirror酱 路径 | 根目录有控制文件、变更文件仅位于 `Assets/`；明确的外层包装目录 | 内存小 zip 验证路径解释，不剥掉实际应保留的路径，能读到根目录 metadata |
| CDK 编辑 | 有效配置下提交无效候选值后取消；验证成功；切换来源后旧验证结果才返回 | 复用命令和组件测试，失败或取消保留原 CDK、来源和验证状态，成功才提交，迟到结果不覆盖新来源 |
| 隐藏来源 | 通过临时入口显示并选择隐藏来源，再关闭和重新打开选择界面 | 根据最终产品决定验证入口可发现、选择结果及临时显示范围；复用组件测试并人工检查实际入口 |
| 空写入计划 | 无待写文件但有删除项，或仍需安装运行库；完全无剩余工作 | 计划和会话测试验证前两者仍执行必要工作，只有最后一种进入已最新路径 |
| 卸载数据与错误 | 包内默认用户数据已被修改、安装后新增用户数据，分别选择保留或删除；文件缺失；实际文件删除失败 | 清单单测验证两类用户数据使用相同保留规则，缺失文件视为已删除，内层删除错误进入最终结果并保留重试所需信息；已有卸载 e2e 补入一个被修改的包内用户数据文件 |
| 应保留的更新行为 | 已有用户数据、缺失默认数据、非空忽略目录；运行库安装失败 | 复用计划与会话测试，已有数据不覆盖、缺失默认数据补齐、忽略目录跳过，运行库失败提示后允许应用安装结束 |

以下场景涉及真实权限或进程退出，使用少量隔离 Windows 环境验证。记录使用的身份、权限和实际结果；尚未执行或环境不支持时明确记为未验证。

| 受保护目录与普通用户目录安装 | 同卷 rename 后实际 ACL 符合目标位置要求，已有显式权限保留；提权写入期间普通用户不能替换暂存内容 |

## Risks

放宽名称读取不会让已发布的严格读取器自动支持新名称；生成带这些条目的安装包需要使用修正后的安装器模板。兼容性验证关注新读取器读取既有生产格式，以及相同输入保持相同编码，不通过扩字段、改魔数或改字符串编码解决限制。

移除 512 限制后仍需保留文件长度和偏移检查，避免扫描命中的伪条目越界。普通文件名是否合法与旧包中的内部标识是否有效需要分开判断，不能误伤既有保留条目。索引超过 255 字节时只能明确拒绝，无法在不改格式的前提下完整表达。

ACL 修复必须同时考虑已有显式权限和新文件继承关系，不能以“统一权限”为由扩大访问或撤销管理员设置。退出清理入口必须只处理记录的暂存根；取消性能优化也不得绕过在途写入结束这一清理前提。

恢复隐藏来源入口和运行库失败后的完成方式属于产品行为，实施时应保持上述约定；若选择改变，需先更新本提案的决策和验收条件。未发现有足够证据独立立项的性能回归，不增加缓存、全局重试框架或额外性能测试体系。
