# 跨账号提权下的安装范围与文件权限

Status: proposed

## Problem

安装器由未提权的启动进程承载界面，需要权限的操作交给以 `headless-uac` 启动的提权子进程；是否提权在最终目录确定时才决定。标准用户在 UAC 凭据提示中输入另一个管理员账号时，子进程以该管理员身份运行，按用户的状态分属两个账号。NSIS、Inno Setup 在按机器安装时以管理员身份重启整个安装器，文件、记录与快捷方式都属于同一身份，不出现这种拆分。

| 问题 | 触发条件与后果 | 代码依据 |
|---|---|---|
| 提权安装仍写 HKCU | 最终目录已有 HKCU 记录且目录需要提权时，登记计划沿用 HKCU，由启动进程写入；快捷方式却按提权放在公共目录。安装范围在一次安装内不一致，跨账号时记录属于启动用户、文件由管理员写入。 | [登记计划](../../../native/installer/registry.rs)、[安装收尾](../../../native/session/run.rs) |
| 暂存目录由子进程创建、由启动进程清理 | 暂存根由子进程按自己的 `%TEMP%` 计算；自替换后的退出清理由启动进程以自身身份启动。跨账号时暂存目录位于管理员的临时目录，启动用户无权删除。同账号下安装目录不在系统卷时，暂存目录位于安装目录旁，受保护位置同样删不掉。 | [暂存位置](../../../native/fs/staging.rs)、[退出清理](../../../native/installer/uninstall.rs) |
| 子进程日志写到另一个账号 | 子进程把日志写入自己的 `%TEMP%\KachinaInstaller.log`。同账号时与启动进程共写一个文件；跨账号时落在管理员的临时目录，启动用户拿不到。 | [日志初始化](../../../native/main.rs) |
| 暂存文件的 ACL 随 rename 进入目标 | 同卷时暂存目录在临时目录，提交通过 rename 放入目标，文件保留暂存位置的 ACL。同账号装入 Program Files 后，文件对该用户可写：之后 `prefer-user` 判定目录可写而不再提权，任何以该用户权限运行的程序都能替换已安装的可执行文件。提权写入期间，暂存内容本身也可被该用户替换，再由提权进程放进受保护目录。 | [暂存位置](../../../native/fs/staging.rs)、[文件提交](../../../native/fs/commit.rs)、[提权判定](../../../native/session/types.rs) |
| 映射盘与 `subst` 盘在提权令牌中不可见 | 启动进程按用户会话中的盘符判断目录；`EnableLinkedConnections` 为默认值时，提权令牌看不到该用户映射的网络盘和 `subst` 盘，子进程写入失败。跨账号时访问 UNC 共享使用的也是管理员凭据。同账号提权同样触发。 | [目录检查](../../../native/installer/mod.rs) |
| 卸载按本次是否提权选择快捷方式位置 | 卸载用 `get_dirs(settings.elevate)` 只清理一侧。按用户安装后改为按机器更新时，更新不重建应用快捷方式，用户目录中的快捷方式在卸载后残留。 | [卸载](../../../native/session/run.rs)、[快捷方式目录](../../../native/installer/lnk.rs) |

本提案取代[重构审阅修复](./2026-09-20-refactor-review-fixes.md)中暂存 ACL 一项，并修改[根据安装记录决定注册行为](./2026-09-20-install-identity-registry.md)中提权时保留 HKCU 归属的部分；其余登记规则不变。

## Proposal

### 提权即按机器安装

本次需要提权时，安装范围为机器：登记只写 HKLM，快捷方式放在公共开始菜单和公共桌面，文件由子进程写入。不需要提权时维持按用户安装，规则不变。提权来源仍是目录按 `uacStrategy` 的判定与已有 HKLM 记录两项；`force` 策略下目标位于用户配置目录时同样按机器安装，与 NSIS、Inno Setup 一致，不拒绝。

需要提权且存在同名 HKCU 记录时，区分三种情形：

| 情形 | 登记行为 |
|---|---|
| 更新 HKCU 记录所在目录 | 子进程先写 HKLM，成功后启动进程删除该 HKCU 记录；HKLM 写入失败时保留 HKCU 记录，按 `REGISTRY_WRITE_FAILED` 提示 |
| 用户把目录改离发现位置，发现目录的记录在 HKCU | 与更新相同：在新目录写 HKLM，成功后删除发现目录的 HKCU 记录，保持[按记录决定注册行为](./2026-09-20-install-identity-registry.md)中不另建记录的规则 |
| 新建安装，HKCU 记录指向其他目录且未经用户改路径 | 只写 HKLM，不修改 HKCU 记录；同名的两条记录按 `InstallLocation` 区分 |

登记计划因此同时给出要写的 hive 与要删的 HKCU 记录。HKCU 的读取与删除只在启动进程执行，它们属于启动用户；子进程只写或删 HKLM，`WriteRegistry` 与 `RemoveRegistry` 去掉 `hive` 字段，由类型保证子进程不打开自己的当前用户键。

卸载在有 HKLM 记录或目录需要提权时提权；匹配的 HKCU 记录仍由启动进程删除。快捷方式两侧都清理，启动进程删除用户目录中的一份，子进程删除公共目录中的一份，覆盖范围迁移后遗留的用户快捷方式。

### 子进程拥有自己创建的状态

提权会话中，暂存目录由子进程创建、使用和清理。自替换后的退出清理由启动进程在现有位置通过 IPC 把暂存根告知子进程；子进程在启动进程退出后才启动清理命令，命令继承管理员令牌。启动进程与子进程映射同一个程序文件，只有两者都退出后暂存目录才能删除；同一进程内的后续会话打开的是按安装目录确定的同一暂存根，提前启动的清理会删掉后续会话的 `journal` 与 `old\` 备份。

每个需要提权的会话启动自己的子进程，每次开始都经过 UAC 同意；WebView、原生界面与静默安装相同。会话结束时关闭管道，子进程随之退出，启动进程不能再让它执行操作。子进程登记了退出清理时，会话结束先让它退役：此后的操作一律拒绝，管道保留到启动进程退出，清理时机与上文相同。暂存目录 `lock` 记录启动进程的 PID，子进程从管道取得；同一启动进程的后续会话据此把上一会话留下的暂存根认作自己的，不报占用。子进程在启动进程之前崩溃时没有人清理，残留由下次打开暂存目录时删除，与现有兜底相同。

未提权会话的暂存与退出清理维持由启动进程负责。

### 日志写回启动用户

启动进程通过命令行参数把日志路径传给子进程，与管道名的传递方式相同。经 `ShellExecuteExW` 的 runas 启动的进程由系统按目标账号生成环境块，不继承启动进程的环境变量，所以不用环境变量传递。管理员对用户配置目录有完全控制权限，新建文件继承临时目录的 ACL，启动用户可读可删。子进程的其他落盘诊断，例如[崩溃捕获](./2026-08-28-crash-capture.md)计划写入 `%TEMP%` 的 minidump，同样使用启动进程传入的位置，否则下次由启动用户运行时找不到并上传。

### 提权写入的暂存位置

写入进程持有提权令牌时，暂存目录放在安装目录旁的 `<安装目录名>.kachina-staged`，不使用临时目录。判断依据是写入进程自身的令牌，而不是会话是否要求提权：启动时已提权的进程在 `prefer-user` 下会判定 Program Files 可写、不经子进程直接写入，同样会把临时目录的 ACL 带进受保护目录。暂存目录继承的是安装目录父目录的权限，可能比安装目录本身宽；新建暂存目录时把安装目录的 DACL 以受保护、全部显式的形式复制到 `new\`，暂存文件从创建起得到与直接建在安装目录中相同的 ACL，rename 后保持不变。安装目录尚不存在时与暂存目录同父，不复制。暂存内容在提权写入期间不可被启动用户替换；同卷由构造保证。未提权的写入进程仍按现有规则优先使用临时目录：目标本身对该用户可写，暂存 ACL 不扩大访问；文件只对该用户与管理员可访问，符合按用户安装的范围。

### 映射盘与 `subst` 盘

会话需要经独立子进程提权时，开始前检查最终目录所在盘符：盘符为网络映射或 `subst` 时拒绝，给出说明原因与建议改用本地路径或 UNC 路径的错误码 `ELEVATED_DRIVE_UNAVAILABLE`。未提权会话与启动时已提权的进程在自己的令牌下写入，看得到自己的盘符，不受影响。

## Alternatives considered

- 需要提权时以管理员身份重启整个安装器：与 NSIS、Inno Setup 一致，身份天然统一。但提权在界面选定目录后才决定，重启需要转移界面与会话状态，界面进程也会以管理员身份运行；拆分模型在规定"提权即按机器安装、子进程只碰机器范围和自己创建的状态"后能达到同样的一致性。
- 提权时保留 HKCU 记录归属：跨账号时记录属于启动用户而文件属于管理员，与公共快捷方式的范围矛盾。
- 退出清理仍由启动进程执行：无法删除管理员临时目录或受保护位置中的暂存目录。
- 整个进程共用一个子进程，一次 UAC 覆盖所有会话：失败后回到首页再点带盾牌图标的按钮是一次新操作，却不经同意就以管理员权限执行。跨账号时管理员只批准了第一次操作，此后启动用户在窗口存续期间可以驱动子进程写入任意位置。- rename 后把 ACL 重置为继承：权限结果相同，但每个提交项多一次安全描述符写入；复制到 `new\` 每个会话只写一次。
- 暂存目录放在安装目录内：新文件继承安装目录自身的可继承权限，但暂存内容会进入扫描、卸载与空目录清理的范围，目录级提交单元也需要避开它。
- 把启动用户的临时目录传给子进程并加入暂存候选：未提权会话中断后 `journal` 留在启动用户的临时目录，下次改为跨账号提权时子进程只查自己的临时目录，部分提交的文件不会被恢复。只有未提权会话在提交中断、且同一目录下次改为跨账号提权时才触发，不为此扩展候选位置。
- 把映射盘解析为 UNC 路径交给子进程：保留这类安装，但跨账号时凭据属于管理员，`subst` 也没有对应的 UNC 形式。

## Acceptance criteria

### 必须满足的行为

1. 提权会话只写或删 HKLM；更新 HKCU 记录所在目录，或用户把目录改离 HKCU 记录所在的发现目录时，HKLM 写入成功后才删除该 HKCU 记录；新建安装不修改其他目录的 HKCU 记录。子进程的 IPC 操作不携带 hive。
2. 提权安装的快捷方式位于公共开始菜单和公共桌面；卸载清理用户与公共两侧。
3. 提权安装到受保护目录后，新文件的 ACL 与在该目录中新建的文件一致，安装目录的权限比其父目录严格时同样成立；启动用户不提权无法写入；之后以 `prefer-user` 运行仍判定需要提权。
4. 每次开始需要提权的会话都弹出 UAC，会话结束后子进程不再执行操作。提权会话的暂存目录由子进程在启动进程退出后删除；同一进程的后续会话打开同一暂存根时，不因上一会话的 `lock` 报占用。
5. 子进程日志写入启动进程的日志文件。
6. 目标位于映射盘或 `subst` 盘时，需要经子进程提权的会话在开始前以明确错误码拒绝。

### 自动化

| 验证对象 | 场景 | 方式 |
|---|---|---|
| 登记计划 | 需要提权时 HKCU 记录位于最终目录、位于用户改离的发现目录、位于未经改路径的其他目录；已有 HKLM 记录；不提权的现有组合 | 登记计划纯数据单测核对写入 hive 与待删记录 |
| 暂存位置 | 写入进程提权与未提权、同卷与跨卷 | 暂存根选择单测 |
| 暂存 ACL | 安装目录带比父目录严格的受保护 DACL | 暂存单测比较 `new\` 下与安装目录下新建文件的 DACL |
| 子进程退役 | 退役后的子进程再收到操作 | 真实命名管道单测：退役请求成功，此后的操作返回错误 |
| 安装后 ACL | 以提权身份安装到 Program Files 下的测试目录 | [Windows e2e](../../../tests/machine-acl.mjs) 比较已安装目录与文件的 DACL 条目和 Program Files 下另建的对照目录、对照文件。CI runner 已提权，在进程内执行，不经子进程 |

CI runner 以管理员运行，`ManagedElevate` 在进程内执行，自动化覆盖不到子进程、UAC 与跨账号路径。

### 跨账号验收

由标准用户启动安装器，在凭据提示中输入另一个管理员账号。覆盖：两个账号的 HKCU 都不产生记录；暂存目录由管理员身份删除，无残留；日志写入标准用户的临时目录；另一账号从"应用和功能"启动卸载。

### 验证记录

同账号经 UAC 提权的安装、更新与卸载已验证：

- 提权安装只写 HKLM 记录，不写 HKCU；覆盖更新从 HKLM 记录找到安装目录并再次提权。
- 按用户安装后改为提权更新时，写入 HKLM 记录并删除 HKCU 记录；之后卸载删除 HKLM 记录，用户与公共两侧的快捷方式均无残留。
- 提权安装的快捷方式位于公共开始菜单和公共桌面，用户侧不创建。
- 安装到 Program Files 后，文件与目录的权限全部继承自 Program Files，启动用户不提权新建文件与写入已安装文件均被拒绝。
- 安装目录的权限比其父目录严格时，提权更新新增与替换的文件、目录与安装目录一致，启动用户不提权写入被拒绝。
- 更新结束后同级暂存目录已删除。
- 界面中更新在下载阶段失败后，失败会话的暂存目录被删除，安装目录保持原版本，会话结束后子进程退出；回到首页再次更新时重新弹出 UAC，更新成功并替换运行中的更新器。
- 自替换更新与卸载后，暂存目录保留到启动进程退出，由退役的子进程删除；`lock` 记录启动进程的 PID。
- 子进程的 IPC 操作日志写入启动进程的日志文件。
- `subst` 盘上需要提权的安装在启动子进程前以 `ELEVATED_DRIVE_UNAVAILABLE` 拒绝，不弹出 UAC。
- 单测覆盖登记计划各组合、暂存根选择、`new\` 的 DACL 复制、注册表打开错误的分类与退役子进程拒绝后续操作。

未验证：HKLM 写入失败时保留 HKCU 记录；网络映射盘的拒绝；跨账号验收全部项目。

## Risks

已按旧规则安装到受保护目录的文件保留用户可写的 ACL，本提案只保证新写入的文件；未变更的旧文件在被替换前仍可被用户修改。

暂存目录在安装目录旁可见，进程崩溃时残留在该位置，直到下次打开同一安装目录的暂存区。DACL 只复制安装目录本身：子目录上单独设置的可继承权限不作用于放进该子目录的新文件，被替换文件上的显式权限也随替换丢失。

HKLM 写入成功而删除 HKCU 失败时，"应用和功能"中会短暂出现两条同名记录，下次更新时再次尝试删除。启用了 `EnableLinkedConnections` 的机器上，同账号提权能看到映射盘，这类安装原本可以成功；拒绝映射盘对这些机器是回归，换来的是跨账号与默认配置下的明确报错。
