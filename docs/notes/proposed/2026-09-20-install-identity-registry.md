# 根据安装记录决定注册行为

Status: proposed

## Problem

审阅基准为重构前的 `ae461aa9ddd5a8f5e445459e14f5d611921f9938`，审阅对象为 `a52a4c66a9e75d86c130be2e029345a761829c24`。安装身份由路径来源或本次提权状态间接决定，绿色版目录直启更新会新建注册记录，已注册安装从目录启动时又可能写错位置或不写。本提案只处理注册表读写与卸载入口归属；其余审阅修复见[重构审阅问题与修复建议](./2026-09-20-refactor-review-fixes.md)。

### 重构引入的、未明确说明的行为变化

| 问题 | 触发条件与后果 | 代码依据 |
|---|---|---|
| 绿色版更新创建注册记录 | `finish_install` 在有 metadata 时写注册表，未区分绿色版。绿色版在目录内直接更新应保留未注册状态；已有安装记录的版本即使从目录直接启动，也应更新自己的记录。路径来源无法区分这两种情形。 | [路径发现](../../../native/installer/config.rs)、[安装收尾](../../../native/session/run.rs) |

### 旧版本已有且仍未处理的问题

| 问题 | 触发条件与后果 | 代码依据 |
|---|---|---|
| 已注册版本从目录启动时跳过注册表更新 | 基准版本依据路径来源决定是否写注册表，目录直启优先得到 `CURRENT_DIR` 或 `PARENT_DIR`，所以已注册版本也可能被跳过。当前代码取消了该判断，却同时改变了绿色版行为，需要重新表达安装身份。 | [路径发现](../../../native/installer/config.rs)、[安装收尾](../../../native/session/run.rs) |
| 注册记录归属随提权状态变化 | 写入目标只由本次 `check_elevated` 决定，可能在 HKCU、HKLM 产生两条记录，使原记录版本保持不变。现有记录可读也不代表可写；优先选已有键不能单独解决权限问题。 | [注册表读写](../../../native/installer/registry.rs) |
| Mirror酱 缺少 metadata 时跳过登记，已最新时无法修复 | changeset-only 归档受支持，但 `finish_install(None)` 不写任何注册信息；已最新路径同样传 `None`。文件提交与注册表写入不是一个事务，提交后中断或登记失败会留下文件与注册信息不一致。 | [Mirror酱 解压](../../../native/thirdparty/mirrorc.rs)、[Mirror酱 会话和安装收尾](../../../native/session/run.rs) |

### 应保留的设计

绿色版直接更新不创建注册记录。没有记录的旧安装与真正绿色版无法仅凭文件可靠区分，默认保留未注册状态；重新注册应来自明确的安装操作。不增加本地身份标记文件，避免复制目录时携带错误身份。

## Proposal

### 根据当前目录的安装记录决定注册行为

在最终安装目录确定后、开始更新前，识别当前目录是否对应本产品的安装记录。路径来源继续用于发现默认目录，不承担安装身份判断。会话保存识别结果和匹配记录的具体位置，注册表读写及卸载入口处理使用同一结果。

| 操作与识别结果 | 预期注册行为 |
|---|---|
| 更新，存在与当前目录匹配的安装记录 | 更新该记录，保留原 HKCU/HKLM 归属；从目录直接双击更新也相同。 |
| 更新，没有匹配记录 | 按绿色版处理，不创建注册记录。 |
| 更新，同名记录指向另一个目录 | 不修改另一份安装，当前目录按绿色版处理。 |
| 用户执行普通新安装 | 根据本次选定的安装范围创建记录，并在会话中固定目标。 |

匹配同时核对产品键与 `InstallLocation`，规范化分隔符、末尾分隔符及 Windows 路径表示，避免简单字符串前缀匹配。现有 `REG_FOLDED` 兼容路径需要按其实际定位的安装目录核对。HKCU、HKLM 都有候选时按目录选择，不无条件优先 HKLM；两条记录均对应同一目录时，更新两条已确认属于该目录的记录，不自动删除其中一条或迁移安装范围。

[`read_uninstall_metadata_raw`](../../../native/installer/registry.rs)在没有路径匹配时会返回其他记录的 metadata，这种 fallback 不能用于安装身份或当前目录卸载清单。查无记录与读取失败应分开表示；权限错误不能被解释为绿色版。识别不要求先成功解析完整 `InstallerMeta`，否则损坏的 metadata 会把已注册安装误判成未注册。

注册表写入目标由识别结果传给执行侧，不能再由执行侧的 `check_elevated` 重选。需要更新 HKLM 而当前权限不足时，应在提交文件前确定提权需求；HKCU 保持启动用户的归属，换管理员账号提权不应把记录写进管理员的 HKCU。复用现有提权执行路径，不新增后台服务或注册表迁移程序。

绿色版不自动补注册记录或卸载入口，已有文件的正常更新策略不变。

### Mirror酱 登记与已最新修复

注册信息的基本字段与完整文件清单分开处理。已注册版本的 changeset-only 更新仍受支持，已知的新版本号等字段应刷新到匹配记录；缺少完整 metadata 时不得清空或伪造 `InstallerMeta`，保留已有内容并明确提示卸载清单未同步。完整 metadata 可用时正常刷新清单。绿色版在这些路径上仍不登记。该取舍保留现有归档兼容性，但不能保证缺少完整清单时卸载覆盖新加入的文件。

归档根目录与包装目录的路径解释由[重构审阅修复](./2026-09-20-refactor-review-fixes.md)处理；本提案只消费已经定位正确的 metadata 与版本信息。

“已最新”路径也应执行已注册版本必要的登记修复；需要完整 metadata 才能修复清单时，说明缺少的信息，不能把空 metadata 当成成功修复。写入失败保留现有失败提示，并使完成结果能区分“文件更新成功，安装信息更新失败”。文件与注册表不增加跨系统事务，允许下一次运行修复；部分字段写入后失败时，重试应能覆盖成一致结果。无待写文件但仍有删除或运行库工作时，不因本提案改走已最新收尾；该判断见[重构审阅修复](./2026-09-20-refactor-review-fixes.md)。

## Alternatives considered

- 恢复 `install_path_source.starts_with("REG")` 判断：能避免绿色版注册，却再次漏掉目录直启的已注册安装。无条件写注册表或无条件优先现有 HKLM 键，也不能区分当前目录与另一个同名安装。
- 将目录直启的注册表写入失败仅记日志：减少弹窗，但保留了记录未更新的问题。应先识别是否需要登记，绿色版主动跳过，已注册版本真实失败时给出可操作结果。
- 根据卸载器文件存在与否识别安装身份：文件可随目录复制或被删除，不能可靠证明当前目录拥有注册记录。增加标记文件也存在复制后的身份问题，暂不引入。
- 为缺少 metadata 的 Mirror酱 归档强制报错，或把增量归档内容当完整文件清单：前者取消现有支持，后者丢失未变更文件的卸载信息。建议保留兼容并说明清单未同步的限制，完整 metadata 可用时再修复。
- 为所有来源、提权方式与注册状态增加 e2e 组合：维护成本高，且实际网络、调度和 UAC 易导致偶发失败。注册表的关键安装链路纳入 e2e，匹配规则和时序分支使用确定性单测，操作系统权限另用少量隔离 Windows 场景验证。

## Acceptance criteria

### 必须满足的行为

1. 绿色版目录直启更新保持未注册；已注册目录直启更新刷新匹配记录；另一目录的同名记录不被修改；提权状态变化不改变记录归属。无法写入时明确区分文件结果与登记结果。
2. 缺少完整 metadata 时不清空清单、不声称清单已同步；已最新路径能够执行已知信息的登记修复。绿色版在这些路径上仍不登记。

### 注册表 e2e 验收

注册表验收必须运行真实安装器并读取 Windows 注册表，覆盖安装、目录直启更新、绿色版更新和已最新修复。优先扩展[离线安装](../../../tests/offline-install.mjs)、[离线更新](../../../tests/offline-update.mjs)、[已最新](../../../tests/already-latest.mjs)及[卸载](../../../tests/uninstall.mjs)场景，共用[测试工具](../../../tests/utils.mjs)。目录直启更新使用安装目录中的 updater，以该目录为工作目录启动，不传 `-D`，保留实际路径发现过程；需要下载时使用现有本地测试服务。

| 场景与准备 | 执行动作 | 必须核对的结果 |
|---|---|---|
| 普通新安装，两个 hive 均无测试产品记录 | 通过正常安装入口安装测试版本 | 选定范围的 hive 中生成记录，`DisplayVersion` 与包版本一致，`InstallLocation` 指向目标目录；`UninstallString` 指向实际卸载入口，`InstallerMeta` 可解析且与安装清单一致；另一 hive 无重复记录 |
| 已注册目录直启更新 | 将已安装版本更新到下一测试版本 | 文件更新成功，同一注册键的版本和 metadata 刷新，安装路径及 hive 保持不变，另一 hive 不产生重复记录 |
| 记录归属与执行权限不同 | 在 HKCU 准备匹配记录，以同一用户的管理员进程执行目录直启更新；另用一个 HKLM 记录完成机器范围更新 | HKCU 记录仍写回原位置，HKLM 记录仍写回机器范围；两个场景串行执行，不按当前进程权限重新选择登记位置 |
| 绿色版目录直启更新 | 从文件夹具准备无注册记录的应用，再启动 updater 更新；补一个同产品记录指向另一目录的子场景 | 应用文件成功更新；无记录时 HKCU、HKLM 都不新建记录，有其他目录记录时其值保持不变，当前目录不新增卸载登记或卸载入口 |
| 文件已最新，登记内容落后 | 保留匹配的安装路径，将测试记录的版本和 metadata 改成旧值，再运行同版本安装器 | 已知版本和完整 metadata 恢复正确，记录归属不变，应用文件哈希保持不变；单纯返回“已最新”不能算通过 |
| 已注册安装卸载 | 从安装目录运行实际卸载器 | 文件结果符合用户数据保留选项，当前目录所属的注册记录被删除，其他目录的记录保持不变 |

测试直接读取 `DisplayVersion`、`InstallLocation`、`UninstallString` 和 `InstallerMeta` 等值，同时查询 HKCU、HKLM；`InstallerMeta` 按 JSON 内容核对，避免依赖序列化顺序。进程成功退出或日志出现写入成功，都不能替代这些断言。

注册表夹具使用测试专用产品标识和临时目录。相同产品的子场景串行执行，每个场景结束后清理它创建的键和文件，失败路径也要执行清理；不能只沿用现有的目录清理。测试只操作自己的产品键，不触碰真实安装记录。注册表查询使用与安装器相同的注册表视图，避免把另一个视图中的缺失误判为未写入。

这些场景接入既有 Windows e2e 入口，复用安装和更新过程，不为每种来源、宿主和权限组合新增 CI job。同用户管理员执行不能证明跨账号提权正确，跨账号场景按下文单独验收。

### 其余测试场景与预期结果

下表列出需要验证的行为，优先向现有用例补充输入或断言。单测中的执行顺序用通知信号或可控 future 安排，不依赖固定 sleep 或真实网络。各行可以共用测试文件和夹具。

| 验证对象 | 要测试的场景 | 预期结果与验证方式 |
|---|---|---|
| 安装记录选择 | 同目录、不同目录、大小写和末尾分隔符差异、前缀相似但不同的目录、`REG_FOLDED`；两个 hive 同时指向同目录或不同目录；metadata 损坏；读取被拒绝 | 纯数据及读取错误单测验证精确归属，同目录双记录均被选中，不同目录记录不被选中；metadata 损坏不等于绿色版，读取失败不等于不存在 |
| 登记失败与重试 | 文件已提交后登记失败，或只写入部分字段后失败；解除故障后再次运行 | 会话结果明确区分文件成功与登记失败，重试修复目标记录；使用可控注册表写入失败的单测或 Windows 集成测试，核对结果和最终值 |
| Mirror酱 登记 | changeset-only 更新已有注册安装和绿色版 | 会话测试验证已知版本写回原记录、缺少完整清单时保留 `InstallerMeta` 并提示未同步，绿色版不登记。路径解释由[重构审阅修复](./2026-09-20-refactor-review-fixes.md)覆盖 |

### 隔离 Windows 验收

以下场景涉及真实权限，使用少量隔离 Windows 环境验证。记录使用的身份、权限和实际结果；尚未执行或环境不支持时明确记为未验证。

| 场景 | 要核对的结果 |
|---|---|
| 普通用户更新 HKLM 记录，需要提权 | 在提交文件前确定提权需求，最终写回原 HKLM 记录；提权失败不伪装成绿色版或另建 HKCU 记录 |
| 换管理员账号提权，原记录属于启动用户 HKCU | 更新启动用户的记录，管理员账号的 HKCU 不产生该产品记录 |

### 验证记录

实施时在本节记录上述场景对应的测试入口、执行结果和证据位置。自动化用例记录用例名及 CI run/job，人工场景记录环境和观察结果；未覆盖项保留具体缺口。注册表验收失败时输出测试产品的目标 hive、关键字段期望值和实际值，便于区分未写入、写错位置与内容未更新。

审阅对象的既有 CI 记录显示构建、Rust 单测和 12 个 e2e 场景通过，但这些记录没有直接证明新增的注册表验收。上述内容是待实施的验证要求，尚无新增场景的执行结果。

## Risks

没有注册记录的损坏安装默认按绿色版处理，会放弃自动恢复已删除记录的能力；这是保留绿色版行为所需的取舍。重复注册记录的两处写入、文件提交与注册表写入都可能部分成功，不能对用户宣称具有原子性。缺少完整 metadata 的兼容路径仍有卸载清单不完整的限制。
