# 根据安装记录决定注册行为

Status: implemented

## Problem

审阅基准为重构前的 `ae461aa9ddd5a8f5e445459e14f5d611921f9938`，审阅对象为 `a52a4c66a9e75d86c130be2e029345a761829c24`。安装身份由路径来源或本次提权状态间接决定，绿色版目录直启更新会新建注册记录，已注册安装从目录启动时又可能写错位置或不写。本 note 只处理注册表读写与卸载入口归属；其余审阅修复见[重构审阅问题与修复建议](../proposed/2026-09-20-refactor-review-fixes.md)。

### 重构引入的、未明确说明的行为变化

| 问题 | 触发条件与后果 | 代码依据 |
|---|---|---|
| 绿色版更新创建注册记录 | `finish_install` 在有 metadata 时写注册表，未区分绿色版。绿色版在目录内直接更新应保留未注册状态；已有安装记录的版本即使从目录直接启动，也应更新自己的记录。路径来源无法区分这两种情形。 | [路径发现](../../../native/installer/config.rs)、[安装收尾](../../../native/session/run.rs) |

### 旧版本已有且仍未处理的问题

| 问题 | 触发条件与后果 | 代码依据 |
|---|---|---|
| 已注册版本从目录启动时跳过注册表更新 | 基准版本依据路径来源决定是否写注册表，目录直启优先得到 `CURRENT_DIR` 或 `PARENT_DIR`，所以已注册版本也可能被跳过。审阅对象取消了该判断，却同时改变了绿色版行为，需要重新表达安装身份。 | [路径发现](../../../native/installer/config.rs)、[安装收尾](../../../native/session/run.rs) |
| 注册记录归属随提权状态变化 | 写入目标只由本次 `check_elevated` 决定，可能在 HKCU、HKLM 产生两条记录，使原记录版本保持不变。现有记录可读也不代表可写；优先选已有键不能单独解决权限问题。 | [注册表读写](../../../native/installer/registry.rs) |
| Mirror酱 缺少 metadata 时跳过登记，已最新时无法修复 | changeset-only 归档受支持，但 `finish_install(None)` 不写任何注册信息；已最新路径同样传 `None`。文件提交与注册表写入不是一个事务，提交后中断或登记失败会留下文件与注册信息不一致。 | [Mirror酱 解压](../../../native/thirdparty/mirrorc.rs)、[Mirror酱 会话和安装收尾](../../../native/session/run.rs) |

### 应保留的设计

绿色版直接更新不创建注册记录。没有记录的旧安装与真正绿色版无法仅凭文件可靠区分，默认保留未注册状态；重新注册应来自明确的安装操作。不增加本地身份标记文件，避免复制目录时携带错误身份。

## Decision

### 根据当前目录的安装记录决定注册行为

最终安装目录确定时，安装器读取 HKCU、HKLM 中本产品的卸载记录，识别哪些记录属于该目录。路径来源只用于发现默认目录，不承担安装身份判断。会话保存识别结果和登记计划，注册表写入、卸载清单与卸载入口都使用同一结果。

| 操作与识别结果 | 注册行为 |
|---|---|
| 存在与最终目录匹配的记录 | 写回匹配记录所在的 hive；从目录直接双击更新、用户改路径到该目录都相同。匹配记录在 HKLM 时本次需要提权，只写 HKLM，同目录的 HKCU 记录在 HKLM 写入成功后删除；目录需要提权而记录在 HKCU 时的处理见[跨账号提权](../proposed/2026-09-24-cross-account-elevation.md)。 |
| 新安装，最终目录就是启动时自动发现的目录，没有匹配记录 | 按本次安装范围创建记录。 |
| 更新，没有匹配记录，且最终目录就是启动时自动发现的目录 | 按绿色版处理，不创建注册记录。 |
| 更新，同名记录指向另一个目录，且最终目录就是启动时自动发现的目录 | 不修改另一份安装，当前目录按绿色版处理。 |
| 最终目录与启动时自动发现的目录不同，且没有匹配最终目录的记录 | 视为用户放弃旧指向，把与发现目录匹配的记录在原 hive 改到新目录，不另建一条记录；发现目录没有记录时按本次安装范围创建记录。 |

本次安装范围由本次是否提权决定：需要提权时为机器范围，只写 HKLM；否则为 HKCU。本次是否提权只有两个来源：目录按 `uacStrategy` 需要提权；登记计划要写 HKLM。登记计划与提权判定在[登记计划](../../../native/installer/registry.rs)中同一处得出：界面每次改路径都重新计算，CLI 与无界面安装在按参数确定路径时计算。因此开始安装前界面就能显示提权需求，WebView 在安装按钮上显示盾牌图标，原生界面给安装按钮设置需要提权的状态。

匹配同时核对产品键与 `InstallLocation`，统一分隔符、去掉末尾分隔符并忽略大小写，不做字符串前缀匹配。`\\?\`、短文件名和目录联接不视为同一路径。`REG_FOLDED` 记录按其实际定位的安装目录核对。HKCU、HKLM 都有候选时按目录选择，不无条件优先 HKLM。

查无记录与读取失败分开表示。除键不存在外，任一 hive 读取失败（包括权限被拒）都使登记计划以 `REGISTRY_READ_FAILED` 失败，不用其余 hive 的结果凑成一次识别，也不把失败解释为绿色版。读取不触发提权。识别只依赖 `InstallLocation`，`InstallerMeta` 损坏的记录仍被识别为已注册。卸载清单只取与当前目录匹配的记录的 `InstallerMeta`，没有匹配记录时不借用其他记录的 metadata。

登记计划随会话传给执行侧。开始安装后，执行侧不重读注册表识别身份，不用 `check_elevated` 重选 hive，也不追加提权。HKCU 写入留在启动进程；HKLM 写入走现有提权执行路径，子进程不为 HKCU 目标打开自己的当前用户键。HKLM 写入失败时不改写到启动进程的 HKCU，同目录的 HKCU 记录也保留。

绿色版不自动补注册记录或卸载入口：未登记的目录不新增卸载器，也不创建卸载快捷方式，已有文件的正常更新策略不变。卸载只删除与当前目录匹配的记录，HKCU 记录由启动进程删除，HKLM 记录走提权执行路径删除，其他目录的记录保持不变。

### Mirror酱 登记与已最新修复

注册信息的基本字段与完整文件清单分开写入。已注册版本的 changeset-only 更新仍受支持。缺少完整 metadata 时刷新版本、名称、发布者、卸载命令、图标和安装位置，保留已有 `InstallerMeta` 与 `EstimatedSize`，清单未同步只记日志，不向用户提示。完整 metadata 可用时同时刷新 `InstallerMeta` 与 `EstimatedSize`。绿色版在这些路径上同样不登记。该取舍保留现有归档兼容性，但不能保证缺少完整清单时卸载覆盖新加入的文件。

归档根目录与包装目录的路径解释由[重构审阅修复](../proposed/2026-09-20-refactor-review-fixes.md)处理；登记只消费已经定位正确的 metadata 与版本信息。

“已最新”路径同样执行已注册版本的登记修复；缺少完整 metadata 时只修复已知字段并记日志，不把空 metadata 写成清单。写入失败时以 `REGISTRY_WRITE_FAILED` 提示，安装继续完成，与快捷方式、运行库失败的处理一致。文件与注册表之间没有跨系统事务，下一次运行可以修复；部分字段写入后失败时，重试覆盖成一致结果。无待写文件但仍有删除或运行库工作时是否走已最新收尾，见[重构审阅修复](../proposed/2026-09-20-refactor-review-fixes.md)。

## Alternatives considered

- 恢复 `install_path_source.starts_with("REG")` 判断：能避免绿色版注册，却再次漏掉目录直启的已注册安装。无条件写注册表或无条件优先现有 HKLM 键，也不能区分当前目录与另一个同名安装。
- 将目录直启的注册表写入失败仅记日志：减少弹窗，但保留了记录未更新的问题。先识别是否需要登记，绿色版主动跳过，已注册版本真实失败时给出可操作结果。
- 在会话结果中另设登记失败标志：完成页和退出码都不读取它，用户看到的仍是同一个错误提示，只会让注册表成为收尾失败里唯一的特例。
- 根据卸载器文件存在与否识别安装身份：文件可随目录复制或被删除，不能可靠证明当前目录拥有注册记录。增加标记文件也存在复制后的身份问题，不引入。
- 为缺少 metadata 的 Mirror酱 归档强制报错，或把增量归档内容当完整文件清单：前者取消现有支持，后者丢失未变更文件的卸载信息。保留兼容，接受清单暂未同步的限制，完整 metadata 可用时再修复。
- 为所有来源、提权方式与注册状态增加 e2e 组合：维护成本高，且实际网络、调度和 UAC 易导致偶发失败。注册表的关键安装链路纳入 e2e，匹配规则和时序分支使用确定性单测，操作系统权限另用少量隔离 Windows 场景验证。

## Verification

注册表 e2e 运行真实安装器并直接读取两个 hive 的记录值，`InstallerMeta` 按 JSON 内容核对；目录直启更新使用安装目录中的 updater，以该目录为工作目录启动，不传 `-D`。

| 判据 | 结果 |
|---|---|
| 普通新安装：本次范围的 hive 生成记录，`DisplayVersion`、`InstallLocation`、`UninstallString`、`InstallerMeta`、`EstimatedSize` 与安装清单一致，另一 hive 无重复记录 | 通过：e2e |
| 已注册目录直启更新：文件更新，同一记录的版本与清单刷新，安装路径及 hive 不变，另一 hive 无重复记录 | 通过：e2e |
| 绿色版目录直启更新：无记录时两个 hive 都不新建记录；同产品记录指向另一目录时其值不变；当前目录不新增卸载器 | 通过：e2e |
| 已最新且登记落后：版本与完整清单恢复，归属不变，应用文件哈希不变 | 通过：e2e |
| 卸载：删除当前目录的记录，指向其他目录的记录保持不变，用户数据按默认选项保留 | 通过：e2e |
| 管理员进程目录直启更新 HKCU 记录：记录仍写回 HKCU，不按进程权限改写到 HKLM | 通过：e2e |
| HKLM 记录的更新与卸载：更新写回原 HKLM 记录、卸载删除该记录，均经提权子进程执行，HKCU 不产生记录 | 通过：e2e，由同一用户的管理员令牌强制走提权子进程；受限令牌与完整令牌的差别不在覆盖内 |
| 目录可写且匹配记录在 HKLM：开始安装前显示需要提权 | 通过：单测 |
| 安装记录选择：分隔符、末尾分隔符与大小写差异，前缀相似的目录，`\\?\` 前缀；同目录与不同目录的记录；用户改离发现目录；metadata 损坏；读取被拒 | 通过：单测 |
| 提权会话的 hive 选择：只写 HKLM，同目录或发现目录的 HKCU 记录在写入后删除，其他目录的 HKCU 记录保留 | 通过：单测 |
| `REG_FOLDED` 记录按实际安装目录匹配 | 未验证 |
| 登记写入失败时以 `REGISTRY_WRITE_FAILED` 提示，已提交的文件保留 | 未验证 |
| Mirror酱 changeset-only 更新写回原记录并保留 `InstallerMeta` 与 `EstimatedSize`，绿色版不登记 | 未验证；清单为 `None` 时写入不触碰这两个值 |
| 普通用户更新 HKLM 记录时提权失败，不伪装成绿色版或另建 HKCU 记录 | 未验证 |

## Consequences

没有注册记录的损坏安装默认按绿色版处理，放弃了自动恢复已删除记录的能力；这是保留绿色版行为的代价。匹配记录在 HKLM 的安装每次更新都需要提权。文件提交与注册表写入、HKLM 写入与删除 HKCU 记录都可能部分成功，不能对用户宣称具有原子性，由下一次运行覆盖修复。缺少完整 metadata 的兼容路径仍有卸载清单不完整的限制。
