# Win7 上 native 宿主能启动

Status: implemented

## Problem

Windows 7（`x86_64-win7-windows-msvc`）上安装器过不了启动。Win10 / Win11 无这些现象。

Windows 7 没有 `combase.dll`。`windows` 0.62 / `windows-core` 0.62 / `windows-sys` 0.61 按 [windows-rs#3743](https://github.com/microsoft/windows-rs/pull/3743) 把 `CoTaskMemAlloc` 等少数 COM 函数改链到 `combase.dll`，加载器在进入任何安装器代码之前拒载，系统对话框为“计算机中丢失 combase.dll”。[windows-rs#3808](https://github.com/microsoft/windows-rs/issues/3808) 记录同一现象；上游不接受 win7 target 条件编译。[windows-rs#3791](https://github.com/microsoft/windows-rs/pull/3791) 被拒。`windows-link` 0.2 用 `raw-dylib`，DLL 名写在目标文件里，不经过 import lib。`x86_64-win7-windows-msvc` 不改这个名字。未 delay-load 的 win7 release 安装器（2,960,384 字节）常规 IAT 里 `combase.dll` 只有 `CoTaskMemAlloc`；同映像已从 `ole32.dll` 导入 `CoTaskMemFree` / `CoInitializeEx` / `CoCreateInstance`。

`windows::Win32::UI::HiDpi` 的 `link!` 把 shcore scaling API set 写进 IAT。Windows 7 不提供该 API set，加载器同样拒载。

`CreateWindowExW` 收到 `WS_EX_NOREDIRECTIONBITMAP`（`0x00200000`）返回 `ERROR_INVALID_PARAMETER`（`0x80070057`）。安装器对话框为“create window: CreateWindowExW: 参数错误。(0x80070057)”。该 bit 在 SDK 中由 `WINVER >= 0x0602`（Windows 8）门控；Win7 是 NT 6.1。不按版本门控时，`window::create`、`create_hidden` 与 `set_decorations` 在 NT 6.1 上仍传入该 bit。

无配置安装器停在 loading。F5（同 WebView 第二次导航）立刻弹出 `PKG_BROKEN`。`prepare_gui` 已是 `PKG_BROKEN`。不把 `PostWebMessageAsJson` 推迟到首次 `NavigationCompleted` 之后时，`%TEMP%\KachinaInstaller.log`（Win7，build 7601，2026-09-11）为：i18n 第一次 `200` / `done 4072`；`gate@3s` 为 `null i18n ok`；没有 `webview recv ui-state`，也没有 `host msg coerced from string`；`get_ui_state` 在 `navigation completed` 之前回到 host（`08:41:26.590` / `26.594`），随后 `window_show` / `frontend_ready` 的 `PostWebMessageAsJson` 仍无页面 `recv`；导航完成后再 `get_ui_state`，host 有日志，页面仍无 `recv`。页面→host 的 `chrome.webview.postMessage`（invoke）在首次导航上正常。host→页面的 `PostWebMessageAsJson`（事件和 invoke 回包）在首次导航上全部丢失。因此不是 Win7 WebView2 缺少 `postMessage` API。WebView2 约定：`PostWebMessageAsJson` 异步投递；若在投到页面之前发生导航，消息不会送出。Windows 7（WebView2 ~109）上，首次导航完成前的一次 post 还会让该文档后续的 `PostWebMessageAsJson` 也到不了页面。release 关闭 `AreDevToolsEnabled`，无法看前端状态。

## Decision

`combase.dll` 走 `/DELAYLOAD`，加载器启动时不解析它。`resources/win7_delayload.c` 提供 `__pfnDliFailureHook2`：`LoadLibrary` 失败时改加载 `ole32.dll`。`build.rs` 编译该 C 文件，并 `/INCLUDE:__pfnDliFailureHook2` 以免 LTO 丢掉 hook。Win8+ 上 combase 存在，delay-load 第一次调用即成功，hook 不触发。ole32 在 Win7 有 `CoTaskMemAlloc`；Win8+ 上 ole32 仍转发到 combase。

DPI 用整数常量加 `LoadLibraryW("shcore.dll")` / `GetProcAddress`；导出不存在时退回 `SetProcessDPIAware`。不引用 `windows::Win32::UI::HiDpi`。

`no_redirection_bitmap()` 只在 NT 6.2+ 返回 `WS_EX_NOREDIRECTIONBITMAP`，Win7 返回 0。三处创建/调整窗口共用这一结果。Win8+ 用该 bit，窗口不画 DWM redirection surface，给 WebView2 / DirectComposition 用。版本取 `nt_version`（`RtlGetVersion`）。

`PostWebMessageAsJson` 在首次 `NavigationCompleted` 之前入队，成功完成后再刷出。之后的 emit / invoke 回包直接 post。

`webview-devtools` 是独立 Cargo feature，默认关。打开后 release 启用 `SetAreDevToolsEnabled`，F12 与 Ctrl+Shift+I 经 `AcceleratorKeyPressed` 调用 `OpenDevToolsWindow`。不自动弹出。debug 在 attach 后自动打开，右键菜单只在 debug 开。`AddScriptToExecuteOnDocumentCreated` 注入一段 ES5：`error` 与 `unhandledrejection` 走已有 `error` 命令，写入 `%TEMP%\KachinaInstaller.log`。这段不随 feature 开关。

## Alternatives considered

- 降回 `windows` 0.61：与 `webview2-com` 0.39 的 0.62 绑定冲突，且锁里仍有 `windows-sys` 0.61 会单独链 combase。
- 自造 `LIBRARY ole32.dll` 的 `combase.lib` 顶掉 SDK import lib：`raw-dylib` 不读这份 lib，IAT 仍是 combase。
- 在本 crate 再 `windows_link::link!("ole32.dll" … CoTaskMemAlloc)`：只增加 ole32 导入，去不掉 `windows-core` 的 combase IAT（#3808 里已有人试过）。
- EXE `/DEF` 转发导出（#3743 评论）：给映像加上 ole32 转发导出，combase 常规导入仍在。
- 所有系统都去掉 `WS_EX_NOREDIRECTIONBITMAP`：Win8+ 会多一块 DWM redirection surface，mica 与透明合成退化。
- `CreateWindowExW` 失败后再用不带该 bit 重试：能过 Win7，但把已知的版本契约变成运行时试错。
- 只在 `is_win11()` 时带该 bit：Win10 的 WebView2 合成同样用得上。
- 导航完成后再 `PostWebMessageAsJson` 一次，完成前已 post 过回包：`08:41:26.594` 之后仍无 `recv`。
- 只解析字符串 `ev.data`：该日志没有 `coerced from string`。
- 去掉 loading 对 `ui` 的等待：没有状态就没有 `Failed`。
- 当作 Win7 没有 `postMessage`：与页面→host invoke、F5 后 host→页面、以及 Win10 / Win11 同路径矛盾。
- 导航完成后 `ExecuteScript` 调 `window.__kachinaHostMsg`：同一导航上 `PostWebMessageAsJson` 已送达（Win7 build 7601，2026-09-11，`09:04:43.733` `recv ui-state event`；`43.747` `recv postMessage event:ui-state`；`43.749` `recv postMessage reply` 与 `recv ui-state pull`），该路径是重复投递。
- release 默认开 DevTools：给最终用户一条调试面。
- 只在页面里听 keydown：页面没起来或 WebView 吞键时打不开。
- 环境变量开关：默认产物链上打开入口，且要多一处运行时解析。

## Consequences

- 第一次走到 `CoTaskMemAlloc` 时 delay-load helper 会 `LoadLibrary`；Win7 上 hook 改加载 ole32，多一次加载失败再重试。
- `CoIncrementMTAUsage` 经 hook 从 ole32 取址时，Win7 的 ole32 没有该导出，同样在首次调用失败。该 2,960,384 字节 win7 release 未导入它。
- Win7 窗口走普通 DWM redirection surface。Win7 没有 mica。
- 首次导航完成前的 invoke 回包晚到 `NavigationCompleted` 之后。F5 与 Win10 / Win11 走同一条 `PostWebMessageAsJson` 路径。
- 诊断 Win7 须用 `--features webview-devtools` 打 release。无 feature 的 release 不启用 DevTools。未捕获的页面错误会多几行日志。
