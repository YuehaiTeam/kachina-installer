# 文档标准

本仓库全部文档遵循以下规则。文档树的分层与导航见 [README](./README.md)；note 的生命周期与格式在 [notes/AGENTS.md](./notes/AGENTS.md) 单独成文。

## 分层

每件事实只有一个家，由职责所在层成文；其他位置引用它时只放库内相对链接。

| 层 | 内容 | 不应出现 |
|---|---|---|
| `docs/design/` | 设计目标：这个项目提供了什么，按层面（进程入口与 CLI、宿主与 UI、安装会话、下载源与插件、IPC 与提权、打包格式与 builder、遥测与错误上报、前端）各成一篇描述 | 变更叙事、进度状态、任务引用、验证计划 |
| `docs/notes/` | note，仓库中唯一的活动体裁，承载决策、任务与调研 | 当前行为的权威描述、迁移计划 |
| `docs/README.md` | 导航与总览，全库唯一入口 | 文档正文、状态叙事 |

skill 存放在 `.agents/skills/`（harness 自动读取目录），文档引用 skill 时只放相对链接，不复述其内容。

## 书写规则

1. 全库使用简体中文；型号、代码标识符、命令与专有名词保留原文。外部引入的 skill 保留英文原文，不做翻译。
2. 写现状，不写历史。文中不出现"原来这样、后来改成那样"、"此前方案废除"、带日期的定版注记这类变更叙事；只陈述当前机制是什么。有裁决价值的变更记录迁入 notes。
3. 一个事实一个家。同一规则或事实只在一处成文；发现多处重复陈述时，保留权威的一处，其余位置改为相对链接。
4. 进度不进参考文档。待执行、已通过、定型、在途这类状态词不进入 design/ 文档；状态唯一的家是 note 的 `Status:` 行与生命周期目录。删除进度表述时，其背后的判据、实测数字与验收结果不得丢失，应复述进相应 note。
5. 部署与线上数据一律不进文档。线上域名、遥测端点、DSN、密钥、用户规模数据都不出现在任何文档中；机制描述使用抽象角色词（如"错误上报后端"、"计数遥测端点"、"下载调度器"）。
6. 引用必须在库内可解析。只允许库内相对路径与已入库文档的节号；机器绝对路径、写作会话引用、未入库草稿节号、任务编号一律禁止。实测数字须连同测量条件复述进正文。
7. 命名直呼其职。概念名取功能与领域语义，读者凭名字即可知道它是什么。形状与位置类比喻词不作为概念名。
8. 数字带条件。引用实测数字时必须同时交代测量条件，包括构建 profile、target 与测量工具。
9. 一条物理行一个段落，编辑器开启软换行。代码块与表格保持各自结构；避免把多条规则塞进一个段落，也避免处处加粗。

## slop 清单

审计任何文档时按下列各项排查：

- 同一规则多处成文。用特征短语搜索全文，保留一处，其余改为链接。
- 叙事与过程故事，如"previously / now / no longer / used to"式表述、PR 序号、提交叙述。
- 实现状态标记，如"implemented！""future: …"。
- 手工复述本应由源码承担的目录、清单与状态。
- 推理转录，例如逐步实现叙述、测试走查、对明显分支的证明。删掉推导过程，保留结论性的契约。
- 段落墙与强调膨胀。粗体和全大写只保留给真正改变行为的那句话。
- implemented note 中的 spec 话术，如"should"、迁移计划、验收清单。

审计工具：[trim-cot-leakage](../.agents/skills/trim-cot-leakage/SKILL.md)（推理转录泄漏）、[prose-standard](../.agents/skills/prose-standard/SKILL.md)（散文覆盖与编辑判断）。
