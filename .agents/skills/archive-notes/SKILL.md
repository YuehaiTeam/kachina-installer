# 归档 note

本 skill 定义归档操作的流程。note 的生命周期、格式与迁移规则见 [notes/AGENTS.md](../../../docs/notes/AGENTS.md)；判断依据是每篇 note 对未来决策的价值，字数与存龄只是发现线索，不是归档理由。

## 阅读前置

开始判断前先读 notes/AGENTS.md 的生命周期与迁移两节，确认规则没有变化。用当前文档、note 之间的交叉链接判断某条理由是否仍然归属或约束当前行为。

## 新增 note 时的归类

写新 note 时，对涉及同一决策、机制或落选方案的活性 note 做一次范围审计，判断完整取代或部分取代：完整取代的在同一批归档；部分取代的保留并交叉链接；独立成立的保留。逐篇判定去向：

- 已实施、且其理由、落选方案、负向保证、线上语义、所有权边界、安全规则或再引入条件中任一仍可能指导未来改动——留在活性区，长度不论。
- 已实施、且决策已完结、正文不太可能指导未来工作，例如一次性细节、窄适配、已闭环的小缺陷、被取代的实现细节、当前行为在别处已显而易见的过程史——归档。
- 提议未实施——留在 proposed；不再值得做则改 rejected 并诚实说明。
- 被否决、且落选方案仍是诱人且代价真实的错误、note 说明了为何落选——保留作护栏。
- 被否决、且已过时、被取代或不再可能防止重议——整体删除并修复入链。

不设归档配额。逐个检视范围内每篇 note，同类按同一原则归类，边界存疑的记入交接说明。

## 归档步骤

1. 将整篇文件从活性目录移到 archived；路径不含原状态目录名。
2. 正文一字不改。仅在 `Status:` 行下方插入一行 `归档：yyyy-mm-dd`，日期取归档当日。
3. 搜索活性正文中指向该 note 的链接：改为指向当前权威；只有刻意引用历史快照时才改到归档路径。不从该 note 内部修复其出链。
4. 归档完成后，该文件永不编辑、移动、转译或删除。它仍是合法的入链目标，但不是当前行为的权威。

## 验证与报告

归档不改变正文，验证重点是两件事：活性区每篇 implemented note 都被判断过；没有指向归档目录的活性死链。

报告列出：保留的 implemented note、归档的 note、保留与删除的 rejected note，以及每个边界存疑的条目及其字数与判定理由。不声称归档 note 的出链有效。
